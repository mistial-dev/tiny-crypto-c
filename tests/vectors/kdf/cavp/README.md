# NIST CAVP SP 800-108 KBKDF test vectors (KBKDFVS)

Source: `kbkdftestvectors.zip` from the
[NIST CAVP key derivation page](https://csrc.nist.gov/projects/cryptographic-algorithm-validation-program/key-derivation)
(`KDFCTR_gen.rsp` is CAVS 14.4, generated 2013-04-23; the other five are
CAVS 12.0, generated 2012-03-20). The files are works of the U.S. Government
and are in the public domain (17 U.S.C. § 105). They are checked in
unmodified, with their original CRLF line endings (see `.gitattributes`),
copied from the OpenPhysical Kdf108 .NET project's
`tests/Kdf108.Test/res/vectors/SP800-108/` directory, whose own suite runs
all 20,000 vectors. `SHA256SUMS` lists the SHA-256 of every file here, and `tests/test_vector_manifests.py` checks them.

| File | Mode | Cases |
| --- | --- | ---: |
| `KDFCTR_gen.rsp` | Counter | 4800 |
| `KDFFeedbackWithZeroIV_gen.rsp` | Feedback with counter, IV may be empty | 4800 |
| `KDFFeedbackNoZeroIV_gen.rsp` | Feedback with counter, IV never empty | 4800 |
| `KDFFeedbackNoCtr_gen.rsp` | Feedback without counter | 400 |
| `KDFDblPipelineWithCtr_gen.rsp` | Double-pipeline with counter | 4800 |
| `KDFDblPipelineWOCtr_gen.rsp` | Double-pipeline without counter | 400 |

Every file covers ten PRFs (`CMAC_AES128/192/256`, `CMAC_TDES2`,
`CMAC_TDES3`, `HMAC_SHA1/224/256/384/512`). The 4800-vector files have
twelve `[CTRLOCATION=...][RLEN=...]` sections of 40 `COUNT`s per PRF; the
400-vector files have a single `[PRF=...]` section of 40 per PRF.

## Parsing notes

- `L` and `IVlen` are in bits; `FixedInputDataByteLen`, `DataBeforeCtrLen` and
  `DataAfterCtrLen` are in bytes. Every `L` is a byte multiple and `KO` is
  exactly `L / 8` bytes long.
- An `IV =` line with nothing after the equals sign accompanies `IVlen = 0`
  and is an empty IV, not a parse error.
- Counter-mode `MIDDLE_FIXED` sections replace `FixedInputData` with
  `DataBeforeCtrData` / `DataAfterCtrData`.
- Feedback and double-pipeline `CTRLOCATION` values are `BEFORE_ITER`,
  `AFTER_ITER` and `AFTER_FIXED`, where "iter" is `K(i-1)` or `A(i)`.
- `CMAC_TDES2` uses a 16-byte `KI` (2-key TDEA, `K1 || K2`); `CMAC_TDES3` a
  24-byte one.

## How the suite uses them

`make test-full` (`TC_KDF_CAVP=1`) parses every file at run time in
`tests/kdf/cavp.c`. Because the AES key size is fixed per build, the
`CMAC_AES192` and `CMAC_AES256` sections run in `test_kdf_192` and
`test_kdf_256`; every other PRF section runs in `test_kdf`. Each binary
asserts the exact number of vectors it ran and skipped, so all 20,000 vectors
execute exactly once across the three binaries in the full profile.

The default `make test` run uses `tests/kdf/test_vectors.h`, a 60-vector
subset generated by `tools/generate_kdf_vectors.py`. That script recomputes
every selected `KO` with an independent Python reference (hmac/hashlib and
the `cryptography` CMAC primitive) and, for counter mode, with
`cryptography`'s `KBKDFHMAC` / `KBKDFCMAC` as well; it fails on any mismatch.
